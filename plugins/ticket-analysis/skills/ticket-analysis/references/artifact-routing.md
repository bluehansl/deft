# 티켓 산출물 저장 경로 규칙 (도구 무관 — 필수)

티켓(`IT-\d+` 등 이슈 키) 작업 중 생성하는 **파일 산출물의 저장 위치**는 독자(audience) 기준으로 라우팅한다. **스킬(deft agent-teams/multi-round 등) 사용 여부와 무관하게 — 단일 Claude 일반 작업에도 동일하게 — 강제**한다.

- 판별 질문 한 줄: **"작업 도구·팀 바깥 독자(사용자 또는 타팀)가 읽는 완성물인가?"**

| 분류 | 예 | 저장 경로 |
|---|---|---|
| **대외 완성물** (사용자 보고·타팀 공유·배포 파일) | 릴리즈 노트, 핸드오프 문서, 배포 SQL/절차서, QA 컨텍스트, 분석/권고 보고서 | **`$BIV/<소유>/projects/<ID>/`** (레코드 `<ID>.md` 와 같은 디렉토리) |
| **도구/팀 내부물** (통신·연속성·오케스트레이션) | 팀 작업노트(work.md)·역할노트·오케스트레이션 로그·세션 임시물 | 각 도구의 데이터 영역 (예: `~/.claude/plugin-data/deft/...`) — 티켓 디렉토리에 넣지 않는다 |

- 대외 완성물을 배출하면 레코드 `<ID>.md`(팀 작업이면 work.md 에도)에 **그 경로 링크를 기록**한다 — 산출물 위치를 매번 수색하지 않도록 레코드가 포인터 역할을 한다.
- 반대 방향도 금지: 도구 내부물(역할노트·로그 등)을 프로젝트 폴더에 두지 않는다.
- 브라우저로 띄우는 리뷰·검수 문서와 그 내보내기(Export/다운로드) 파일도 티켓 산출물이다 — 프로젝트가 선언된 작업에서는 `$BIV/<소유>/projects/<ID>/` 하위에 생성·관리하고, 브라우저가 기본 다운로드 경로(`~/Downloads` 등)에 떨어뜨린 파일은 감지 즉시 티켓 경로로 이동한다. OS 임시 경로는 임시파일에만 예외적으로 허용한다.
- 이 경로는 옵시디언 볼트(Git+LFS)이며 **볼트 쪽이 자동 커밋**한다. 루트는 `${BIV_ROOT:-$HOME/obsidian-vault/BIV}`.
  `~/.ai/tickets` 는 `fassto/projects` 로의 **하위 호환 별칭**이고 정본은 볼트 경로다 — 별칭은 제거 예정이므로 새 문서·스크립트에 쓰지 않는다.
- deft 스킬 사용 시의 세부 라우팅은 스킬이 자체 소유한다(agent-teams SKILL §3-4-1 — 본 규칙과 동일 사상). 스킬이 없거나 다른 도구를 쓰는 경우에도 본 규칙이 기본값이다.

## 브라우저 리뷰 문서 제출 감시 (필수)

브라우저 리뷰·검수 문서로 사용자 검토를 요청할 때는, **검토 요청 메시지를 보내기 전에** 제출 산출물에 대한 백그라운드 감시를 먼저 걸어둔다 — 제출 버튼 클릭은 에이전트에게 자동 전달되지 않는다.

- 서버형 문서: 제출 파일(예: `feedback.json`)의 완료 상태 전환을 폴링 감시.
- 다운로드형 문서: 내보내기 파일의 신규 생성을 감시하고, 감지 즉시 위 표의 관리 경로로 이동.
- 감시를 걸기 전에 리뷰 요청을 보내지 않는다 (클릭이 감시 시작보다 먼저 발생하면 유실됨).
